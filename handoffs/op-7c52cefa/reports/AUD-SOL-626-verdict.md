[Factory](https://github.com/BradleyGleavePortfolio/growth-project-backend/blob/360d8705acdd73c68b01640b753087bca06819fe/src/ai-egress/provider-clients.ts#L15-L16), [create/stream boundary](https://github.com/BradleyGleavePortfolio/growth-project-backend/blob/360d8705acdd73c68b01640b753087bca06819fe/src/ai-egress/ai-egress.service.ts#L126-L146)

Independent actual-source/actual-installed-SDK probe, separately for **create and stream**: the first intercepted HTTP request withdraws consent and returns 500 with a 1ms retry hint; a second identical client payload is sent with grant=false, after only **one** ledger read; an explicit subsequent wrapper call correctly refuses with 403 (negative control). No external request, real credential, database or customer data was used. This contradicts the PR's every-attempt/next-send withdrawal contract; existing mocked `messages.create` retry tests do not exercise SDK-internal retries. [Claim and test inventory](https://github.com/BradleyGleavePortfolio/growth-project-backend/pull/626)

**Minimal fix:** disable automatic SDK retries in the factory and enforce `maxRetries: 0` at the gate's per-call create/stream boundary (do not let options/injected clients re-enable them); any wanted retry must re-enter the live-consent gate. Add real-SDK mocked-fetch 500/429/connection-error withdrawal regressions for streaming and non-streaming paths. [Affected boundary](https://github.com/BradleyGleavePortfolio/growth-project-backend/blob/360d8705acdd73c68b01640b753087bca06819fe/src/ai-egress/ai-egress.service.ts#L126-L146)
