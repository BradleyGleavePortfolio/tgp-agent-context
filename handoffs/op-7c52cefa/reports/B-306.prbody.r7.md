## Summary (plain language)
- **Policy gate.** `GET /auth/signup-policy` decides whether the role question exists. Today's production backend does not send `role_choice`, so nothing changes for it. Backend #597 sends `role_choice: true` (or `false` when `SIGNUP_ROLE_CHOICE_ENABLED=false`).
- **Role step.** With the gate on and no invite code, CreateAccount opens with "How will you use the app?" (`components/auth/RoleChoice.tsx`): "I'm here to train" or "I coach clients". Arriving with `invite_code` (join link / QR / universal link) skips it; typing a code removes the coach option.
- **Wire.** `intended_role` goes on `/auth/register`, `/auth/apple`, `/auth/google` only when codeless and gated. `/auth/signup-with-code` and any request with a code never carry it.
- **Routing.** Server role only: `user.role === 'coach'` → CoachNavigator; otherwise RoleSelection (client pairing) with a plain notice when the request did not end as chosen.
- **Login providers.** Ask "Already have an account?" before a provider round-trip while the gate is on.
- **Doctrine.** Hairline rows, radius ≤ 4, h3/body tokens, no exclamation marks, no emoji, no celebration; the Login confirm panel uses `Radius.sm` (0) and the forest primary.
