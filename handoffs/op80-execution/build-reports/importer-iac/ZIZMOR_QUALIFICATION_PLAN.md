## Source lock and feasible vulnerability check

The tag's `Cargo.lock` (locally measured source SHA-256 `215f4d154a1cac4dce2e9d000881fc54cba21f77d0838d7d9480ceaa5dbcd188`) contains **450 packages: 441 crates.io registry entries, all with checksums; zero git dependencies; nine same-workspace packages without registry checksums**. This is a useful source lock, not an SBOM and, because the release build omitted `--locked`, not proof of the archive closure. ([tagged Cargo.lock](https://raw.githubusercontent.com/zizmorcore/zizmor/v1.30.1/Cargo.lock))

A separately allocated evidence run could audit that unchanged lock directly with a pinned, independently verified RustSec `cargo-audit` or OSV-Scanner standalone binary, requiring no Python closure and no build of zizmor. That result would qualify the **tagged source lock only**. Binary acceptance additionally requires one of: upstream SBOM/build manifest tied to the attested digest; reproducible build equivalence; or a supported extraction method that identifies the actual compiled crate closure. None was established here, and system-linked library inventory also remains unknown. Do not call a clean lockfile result a clean binary. This is a proposed validation approach, not a verified command/tool installation plan; exact standalone verifier release, hash, lockfile handling and support remain to be qualified. ([RustSec cargo-audit project](https://github.com/rustsec/rustsec/tree/main/cargo-audit))

## Permissions, triggers, pinning and injection boundary

- Permissions: `excessive-permissions` works offline and inspects workflow/job scope, including omitted default permissions. This is broader/different from `CKV2_GHA_1`; do not transfer the historical Checkov 136-check count. ([audit docs](https://docs.zizmor.sh/audits/))
- Triggers: `dangerous-triggers` works offline and detects `pull_request_target` and `workflow_run`. Installed Checkov has no trigger policy; the candidate's separate R120 wrapper/control rejects `pull_request_target`. Qualification should preserve that contract and decide explicitly whether `workflow_run` is newly in scope, rather than silently expanding product policy. ([audit docs](https://docs.zizmor.sh/audits/), [current controls](file:///tmp/tgp-op80-cycle3-importer-iac/test/iac-security-controls.py))
- Pinning: `unpinned-uses` works offline and defaults to full SHA pins for all actions; its policy is configurable. Installed Checkov has no pinning check. Run with configuration disabled so repository policy cannot weaken the default, and test full SHA/tag/branch/unpinned/local-action cases. ([audit docs](https://docs.zizmor.sh/audits/))
- Injection: use regular persona for high-signal native equivalence; pedantic/auditor flag broader template expansions and other persona-only findings. Persona choice changes results and must be fixed and asserted. ([personas](https://docs.zizmor.sh/usage/), [template audit](https://docs.zizmor.sh/audits/))
- Offline: all four audits above work offline. Offline deliberately skips online audits such as impostor commits, known-vulnerable actions, ref confusion and stale-action refs; absence of those results is not a clean online security determination. ([audit inventory](https://docs.zizmor.sh/audits/), [offline behavior](https://docs.zizmor.sh/usage/))

## Authoritative input and suppression-resistance strategy

Do not rely on a directory walk or JSON findings array as inventory. Compute the expected tracked `*.yml`/`*.yaml` files under `.github/workflows/` from the frozen tree, reject an empty set, and pass **each exact path as an explicit argument** with `--collect=workflows --strict-collection --offline --no-config --no-ignores --persona=regular --format=json-v1`. Explicit `.yml/.yaml` files under that directory are classified as workflows; strict collection turns syntax/schema failures into errors; successful registration is deterministic; zero registered inputs produces an error. ([CLI source](https://raw.githubusercontent.com/zizmorcore/zizmor/v1.30.1/crates/zizmor/src/cli.rs), [collection source](https://raw.githubusercontent.com/zizmorcore/zizmor/v1.30.1/crates/zizmor/src/registry/input.rs), [main source](https://raw.githubusercontent.com/zizmorcore/zizmor/v1.30.1/crates/zizmor/src/main.rs))

For stronger per-file proof, invoke each expected file separately and require its expected exit class, then perform one aggregate invocation over exactly the same sorted list; emit the wrapper's expected/invoked/completed inventory with hashes. This avoids `.gitignore`, global-ignore and `.git/info/exclude` omission. `--no-config` disables configuration loading; `--no-ignores` disables inline ignore comments and configured ignore rules. Reject inherited `ZIZMOR_*`, GitHub token and config variables via a clean allowlist; reject any min-severity/confidence, fix, SARIF or no-exit-code flags. ([CLI source](https://raw.githubusercontent.com/zizmorcore/zizmor/v1.30.1/crates/zizmor/src/cli.rs), [ignore implementation](https://raw.githubusercontent.com/zizmorcore/zizmor/v1.30.1/crates/zizmor/src/registry.rs))

Caveat: JSON v1 is a flat findings array, not an authoritative parsed-file manifest. The separate explicit-file process contract is therefore necessary; a single green aggregate invocation alone is insufficient inventory evidence. ([JSON format](https://docs.zizmor.sh/usage/))

## Proposed qualification controls (no execution authorized)

1. **Artifact/provenance red-green:** wrong archive hash and wrong attestation subject/repository/ref fail; exact archive hash plus locally verified attestation pass. Record release JSON, bundle, verifier identity/version and output.
2. **Closure blocker control:** assert release workflow is pinned to expected source and uses locked build. v1.30.1 must currently **RED** because `cargo build` lacks `--locked`; do not waive it.
3. **CLI isolation:** reject inherited token/config/persona/filter/fix/no-exit variables; assert exact offline, regular, strict, no-config, no-ignores, JSON-v1 arguments.
4. **Inventory:** zero workflows, wrong extension, malformed YAML and schema-invalid workflow fail; one invalid among safe files fails; ignored/untracked workflow mismatch fails; all four frozen workflows individually register and aggregate expected=invoked=completed.
5. **Suppression resistance:** an inline `zizmor: ignore[...]` red fixture and repository config ignore red fixture still produce findings under `--no-ignores --no-config`; env-selected config cannot affect output.
6. **Exit/report parser:** accept documented finding exits 11–14 as findings to classify/block; exit 0 only with valid JSON and completed inventory; exits 1–3, timeout, signal, malformed/truncated/non-array JSON, unknown audit/severity/confidence fail closed. Do not use SARIF or `--no-exit-codes`. ([exit codes](https://docs.zizmor.sh/usage/))
7. **Direct mapped reds/greens:** insecure commands at workflow/job/step vs false; every Checkov injection term vs env indirection; scalar `write-all`, omitted/broad/minimal permission maps; `pull_request_target` and `workflow_run` vs `pull_request`; SHA/tag/branch/unpinned action references.
8. **Gap demonstrations:** curl+secret, netcat+IPv4, unsigned recognized image build, build without cosign/SBOM, and nonempty `workflow_dispatch.inputs` must demonstrate that stock v1.30.1 does not cover the five Checkov policies. These expected gaps terminate equivalence; they are not green controls.
9. **No-mutation/exact-tree:** before/after tree and file hashes identical; no network in native audit process; no automatic fixes.

## Decision

Stop qualification before any binary execution unless the parent explicitly authorizes a gap remedy and closure standard. Stock zizmor v1.30.1 is a precisely identified, attested standalone candidate with useful native workflow audits and strong suppression/input-control primitives, but it is **not equivalent** to installed Checkov 3.3.19: five native policies are absent, and the shipped binary lacks an SBOM/authoritative lock linkage because its attested build did not use `--locked`. No candidate, prior evidence, product, rules, gates or remotes were changed; all execution resources remain released.
