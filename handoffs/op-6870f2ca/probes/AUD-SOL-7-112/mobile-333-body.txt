## What it checks (`node scripts/check-expected-env.js --list --profile clinic`)
| Profile | Values that must be set and real | Stripe |
|---|---|---|
| **clinic** | `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_STRIPE_PUBLISHABLE_KEY`, `EXPO_PUBLIC_SENTRY_DSN` | `pk_live_` |
| production | same five | `pk_live_` |
| preview | the four `kind: "required"` names | `pk_live_` or `pk_test_` |
| development | skipped | — |

Each value is rejected when:
- **Placeholder:** empty, `your_…_here`, `REPLACE_WITH_*`, `<…>`, `${…}`, `changeme` / `todo` / `xxx`, or a copied masked `*****`.
- **URL** (`API_URL`, `SUPABASE_URL`, `HELP_BASE_URL`): not `https`, or the host is localhost, an emulator or private IP, `example.*`, or `*.invalid` / `*.test` / `*.local`.
- **Supabase anon key:** it must be one of two complete keys.
  - A JWT with three non-empty base64url parts, a signed header (`alg` set, not `none`), role `anon`, a signature of at least 32 bytes, and an `exp` that has not passed.
  - Or an `sb_publishable_` key followed by at least 20 letters, digits, `_` or `-`.
  - A **service_role JWT** or an **`sb_secret_`** key fails, because either would ship an RLS bypass in the bundle. The service-role check runs first, even when the token is malformed in other ways.
- **Sentry DSN:** not of the form `https://<key>@<host>/<id>`.
- **Stripe key:** it must be a complete publishable key: `pk_live_` or `pk_test_`, then 24 to 247 letters and digits, and not one repeated character. A test key fails on a store profile.
- **URL hosts (C-333-1):** these also fail:
  - 172.16/12, 100.64/10 (CGNAT), 169.254/16 and 0/8;
  - IPv6 loopback, unspecified, ULA (`fc00::/7`), link-local and IPv4-mapped;
  - `*.internal`, `*.lan`, `*.home.arpa`;
  - single-label names.
- **No value text in logs (B-333-3):** every failure message is fixed text. The URL scheme is no longer echoed.
- These are shape checks only. They make no network call to Stripe, Supabase or Sentry.

**Build parity:** for clinic, every resolved `eas.json` `build.clinic.env` value must reach the build unchanged:
- the 7 clinic `EXPO_PUBLIC_FF_*` / mock flags
- `EXPO_PUBLIC_FF_IOS_HIDE_NON_P2P_PURCHASES`
- `EXPO_PUBLIC_NOTIFICATIONS_MOCK`, `EXPO_PUBLIC_USE_MOCK_COMMAND_CENTER`
- `TGP_ANDROID_HEALTH_CONNECT`

The existing secret-shaped-name check stays.

## How it runs
- **EAS:** `"eas-build-pre-install": "node scripts/check-expected-env.js --eas-hook"`.
  - It runs before `npm install`, so it fails fast and saves build minutes on the Free plan. It needs only Node built-ins: no TypeScript, so the source scan is left to CI.
  - The profile comes from `EAS_BUILD_PROFILE`. A non-release profile is skipped. An unset profile fails closed.
- **Operator, before queueing a build:** `eas env:exec production 'npm run check:release-env -- --profile clinic'`.
- `scripts/eas-profile.js` resolves `extends` the way EAS does. It is byte-identical to the copy in mobile #305, so the two PRs add the same file and merge without conflict in either order.
