**Findings**
- **C-646-1 (optional, defense in depth): owner admin routes still return raw rows with the client's secrets.** `src/checkout/payment-ops.controller.ts:145-154` (`GET /v1/admin/payments/purchases`, raw `findMany`) and `:165-168` (`GET /v1/admin/payments/purchases/:id`, `include: { package: true }`) send `stripe_client_secret` and `stripe_ephemeral_key` to the owner console (SSR, JWT + ADMIN_SERVICE_TOKEN). The owner already holds the Stripe secret key, so this gives no new access. It does put live customer payment credentials into console responses and server logs. Minimal fix: an `ADMIN_PURCHASE_SELECT` (every column except the two secrets) on those two reads. Keep the Stripe ids for support.
- **C-646-2 (optional): cached secrets are never cleared.** `checkout.service.ts:673-681` stores `stripe_client_secret` / `stripe_ephemeral_key` and nothing ever nulls them, even after the PaymentIntent is terminal (paid / canceled / refunded). Clearing both columns in the `payment_intent.succeeded` / `canceled` webhook transitions shrinks the at-rest exposure of any future raw read to zero. Replay only matters while the purchase is `pending`.

**Outside this diff (operator attention, launch risk; not a #646 finding)**
- Mobile `src/components/PackageSelectionSheet.tsx:288-301` (main f34b5b99, unchanged in every open mobile PR) POSTs `{ package_id, idempotency_key }` to `/v1/checkout/sessions`. Backend `CreateCheckoutDto` (`checkout.controller.ts:44-64`) has no `idempotency_key`, and `main.ts:99-100` sets `forbidNonWhitelisted: true`, so this returns 400. Even a valid call returns `{ session_id, url, purchase_id, status, package }`, not `stripe_client_secret` / `stripe_ephemeral_key`, and `initPaymentSheet` gets no `customerId`. The Day 1 / RootNavigator package sheet therefore cannot take a payment and shows the generic "Payment failed. Please try again." The PR body's statement that mobile reads secrets from the `/v1/checkout/sessions` mint is inaccurate. Mobile never calls `POST /v1/checkout/payment-intent`, the route that returns `client_secret`, `ephemeral_key`, `customer_id` and `publishable_key`. Recommended default: a mobile slice switches the sheet to `/v1/checkout/payment-intent`, passes `customerId`, and maps 409 COACH_NOT_CONNECTED / COACH_NOT_PAYOUT_READY / 503 PAYMENT_IN_PROGRESS / PAYMENT_RETRY to specific copy.
