### Prior findings
- **B-635-2 (mine: only today's chat could be deleted): CLOSED.**
  - **New routes.** `RomanChatsController` (`src/roman/roman-chats.controller.ts`) adds:
    - `GET /roman/sessions`: the caller's live chats, metadata only, keyset on `(started_at, id)`. A cursor that is not one of the caller's own rows is a coded 400 `ROMAN_CURSOR_INVALID`.
    - `DELETE /roman/sessions`: every chat on both surfaces, every day, plus the caller's own legacy tombstones. Returns 204 when nothing is left.
    - `DELETE /roman/sessions/:id`: any day's chat.
  - **Guards.** The controller is JwtAuthGuard + RolesGuard, outside `RomanFeatureGuard`, so the kill switch never takes away the right to delete. Every route sends `no-store`.
  - **Scoping and failure.** Every read and write is scoped by `user_id` (`roman.service.ts` `listSessions`, `deleteSession`, `deleteAllSessions`). Each row is erased in its own transaction. A failure part-way is a coded 503 `ROMAN_ERASE_INCOMPLETE` (all-chats message), and a retry finishes the rest.
  - **Daily cap.** The cap is kept, because erased shells keep the in-window turn count.
  - **Tests:** `roman-chats.controller.spec.ts` runs Nest over HTTP with the real CacheControlInterceptor and the flag OFF. The live Postgres cases "delete-all erases prior days and today on both surfaces, nobody else, cap kept" and "prior-day chat erased by id; repeat 204; foreign id coded 404" PASS in [mwb-3-live-tests](https://github.com/BradleyGleavePortfolio/growth-project-backend/actions/runs/37045086303/job/110964408062) (11/11).

### New hunt (security, tenancy, idempotency, races, copy)
- **Route collision.** Express matches on method plus path. `GET /roman/sessions` and both DELETEs exist only on `RomanChatsController`, and `RomanController` no longer declares a DELETE.
- **Cursor.** A cursor cannot read another user's row, because the anchor lookup is scoped by `user_id`.
- **Concurrency.** `deleteSession` re-reads once when its compare-and-set loses, and `appendMessage` against an erased row is the coded 404.
- **Copy.** The new messages have no exclamation marks or emojis, and each one names a next step.
- **Fix.** `?limit=30` on the messages list now converts with `@Type(() => Number)`.

**C-635-4 (optional): a `sub_coach` account cannot list or delete its own Roman chats.**
- `roman-chats.controller.ts` declares `@Roles('student', 'coach', 'owner')` on all three routes.
- `roleSatisfies` (`src/auth/roles.guard.ts:67-75`) gives `sub_coach` no inheritance, so such a user gets 403 "Insufficient role".
- A `sub_coach` cannot open Roman either, so this only bites a user whose role changed after chatting. Their chats would stay until account deletion.
- Minimal fix: add `'sub_coach'` to `@Roles` on the three list/delete routes (deletion rights should not depend on role), with a controller-spec case.
